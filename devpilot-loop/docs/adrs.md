# Architecture Decision Records

## ADR-001: Manager-Worker-Skill 三层解耦架构

**状态**: Accepted  
**日期**: 2026-08-13  
**背景**: 需要支持多 Agent 协作，同时确保技能可独立复用

**决策**: 采用 Manager-Worker-Skill 三层解耦架构，Manager 负责编排，Worker 负责执行，Skill 提供能力

**后果**: 
- ✅ 技能可独立安装/卸载/测试
- ✅ Worker 可独立替换无需修改 Manager
- ✅ 跨场景复用成本低
- ⚠️ 增加了配置复杂度（7 个 config.yaml）

**替代方案**: 单体架构（所有逻辑在一个 Agent 中）— 被拒绝，因为不可复用

## ADR-002: 零信任凭证管理

**状态**: Accepted  
**日期**: 2026-08-13  
**背景**: Agent 需要访问外部 API，但不能直接持有密钥

**决策**: Consumer Token + Higress AI 网关 + SHA-256 哈希存储

**后果**:
- ✅ 零凭证泄露风险
- ✅ 单点安全边界（网关）
- ✅ 密钥轮换支持
- ⚠️ 增加网关依赖

**替代方案**: 环境变量注入 — 被拒绝，因为不符合零信任原则

## ADR-003: OpenTelemetry 可观测性

**状态**: Accepted  
**日期**: 2026-08-13  
**背景**: 需要全链路追踪以实现可审计性

**决策**: 使用 OpenTelemetry SDK + Auto-instrumentation，支持本地和远程 Exporter

**后果**:
- ✅ 端到端 Trace 关联
- ✅ 与 Prometheus/Grafana 兼容
- ✅ 生产就绪
- ⚠️ 需要额外的基础设施（Jaeger/Prometheus）

**替代方案**: 简单日志 — 被拒绝，因为缺乏结构化追踪能力

**状态**: Accepted  
**日期**: 2026-08-13

## ADR-005: 三级权限 RBAC

**状态**: Accepted  
**日期**: 2026-08-13  
**背景**: 不同 Agent 需要不同级别的操作权限

**决策**: L1 只读 → L2 写(需确认) → L3 生产(需审批)

**后果**:
- ✅ 最小权限原则
- ✅ 清晰的安全边界
- ✅ 可审计的操作日志
- ⚠️ 增加审批流程复杂度

**替代方案**: 全权访问 — 被拒绝，因为安全风险过高

- ⚠️ 需要持续维护证据文件
