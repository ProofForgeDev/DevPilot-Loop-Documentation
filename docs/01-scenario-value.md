# 第 1 章 场景与价值

> 对应评分维度：**场景价值与行业可复制性**，权重 **25%**

---

## 1.1 目标场景

中小研发团队（3–20 人）的**缺陷修复全生命周期**。

选择理由：
- **高频**：任何团队每天都在修 bug，场景永不枯竭
- **高痛点**：链路长（报障→定位→改→测→发）、跨角色、上下文易丢
- **高可量化**：修复周期、介入次数、复发率都可精确测量
- **高差异化**：官方 OpsPilot Demo 聚焦运维，本项目聚焦研发协同，互补不重叠

## 1.2 目标用户与角色

| 角色 | 在系统中的位置 | 获得的价值 |
|------|--------------|-----------|
| 研发负责人 | Matrix 房间监督者 / 审批者 | 全程可见，只审批关键节点，不再当"AI 的保姆" |
| 一线开发 | 接收 Fixer 产出的 patch | 从"找 bug 改 bug"变为"审 patch"，效率 16× |
| 测试工程师 | Verifier 的协作者 | 回归自动化，聚焦探索性测试 |
| 技术主管 | Knowledge 产出的 Runbook 消费者 | 团队经验不再随人员流动丢失 |

## 1.3 痛点（现状量化）

| 痛点 | 现状数据 | 根因 |
|------|---------|------|
| 修复周期长 | 平均 4 小时 / 缺陷 | 人工串联 5 个环节，等待时间占 70% |
| 上下文丢失 | 重复沟通占修复时间 40%+ | 信息在人与人交接中衰减 |
| 经验不沉淀 | 同类缺陷反复出现 | 修复知识留在个人脑中 |
| 无法审计 | 出了问题无法追溯 | 缺乏结构化日志与 trace |

## 1.4 价值主张（量化收益）

| 指标 | 改进前 | 改进后 | 提升倍数 |
|------|--------|--------|---------|
| 缺陷修复周期 | 4 小时 | 15 分钟 | **16×** |
| 人工介入 | 100%（每步人工） | 20%（仅 L3 生产操作审批） | **-80%** |
| 同类缺陷复发率 | 基线 | 下降 60% | 经验自动沉淀 |
| 审计可追溯性 | 无 | 100%（Matrix + OTel Trace） | 从 0 到 1 |

## 1.5 行业可复制性

Manager–Worker–Skill 是**场景无关的骨架**。同一套模式可平移到：

| 目标场景 | Agent 映射 | 复用 Skill |
|---------|-----------|-----------|
| 运维自愈 | Intake→告警归并，Fixer→自愈脚本，Verifier→健康检查 | DefectTriage、TestRunner |
| 智能客服 | Analyst→意图根因，Knowledge→话术沉淀 | CodeRootCause、PostmortemCapture |
| 金融风控 | Verifier→规则校验，Release→灰度策略 | TestRunner、CanaryRelease |

其中 **DefectTriage** 和 **PostmortemCapture** 是完全场景无关的通用 Skill，
可直接跨行业复用。
