# 审计方法论

## 证据分级体系 (DAL 类比)

本审计体系参考 ISO/SAE J3016 自动驾驶分级方法论，为 AI Agent 系统建立四级证据可信度框架：

### L1 - 实机输出 (Authentic)
- **定义**: 直接来自系统的原始输出
- **来源**: 截图、日志文件、API 响应、命令行输出
- **验证方式**: 可直接复现
- **示例**: Docker compose ps 输出、Matrix 房间消息、测试报告

### L2 - 系统分析 (Systematic)
- **定义**: 对系统内部结构的系统性分析
- **来源**: 源代码审查、配置检查、API 规格验证
- **验证方式**: 代码追踪、配置对比
- **示例**: Agent config.yaml 完整性、Skill 接口实现、数据库 schema

### L3 - 演绎推理 (Deductive)
- **定义**: 基于已知事实的逻辑推导
- **来源**: 架构分析、威胁建模、性能推算
- **验证方式**: 同行评审、逻辑审查
- **示例**: DAL 模型设计、安全架构合理性、扩展性分析

### L4 - 独立验证 (Independent)
- **定义**: 使用独立工具或第三方评估
- **来源**: 外部扫描器、基准测试平台、审计报告
- **验证方式**: 可复现的自动化测试
- **示例**: Bandit 安全扫描、SWE-bench 基准、代码复杂度分析

## 证据收集流程

```
1. 识别证据需求
   ↓
2. 选择合适层级 (L1-L4)
   ↓
3. 执行收集程序
   ↓
4. 记录元数据 (时间戳、工具版本、参数)
   ↓
5. 存入对应目录
   ↓
6. 更新 evidence_index.json
```

## 验证链完整性

每个 L4 证据文件包含以下元数据：
- `evidence_id`: 唯一标识符 (E01-E48)
- `tier`: 证据层级 (L1-L4)
- `source`: 数据来源描述
- `tools`: 使用的工具及版本
- `execution_date`: 执行日期
- `summary`: 关键结果摘要
- `detailed_results`: 完整结果

## 不可篡改保证

- 所有 L1 证据保留原始格式
- L2/L3 证据提供引用路径
- L4 证据包含工具版本哈希
- 元数据使用标准 JSON 格式

## 与评分维度映射

| 评分维度 | 权重 | 主要证据层级 |
|----------|------|--------------|
| 场景价值与行业可复制性 | 25% | L1, L3 |
| 多 Agent 协同设计 | 25% | L1, L2, L4 |
| Skill 工程化设计 | 25% | L1, L2, L4 |
| 工程落地与安全可审计 | 20% | L1, L2, L3, L4 |
| 开源贡献与生态复用 | 5% | L2, L3 |
